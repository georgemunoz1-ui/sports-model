# A predicted margin is not a betting spread — render it with the team, the direction in words, and the negated fair spread.
Rule: home_margin_pred = home points - away points. NEGATIVE means the HOME team LOSES. The fair home spread is the NEGATION. Never print the raw signed margin in spread notation; print "TEAM projected to lose by X (fair spread TEAM +X)".
Incident: corrected TWICE. 2026-08-20 blended margin and fair spread on TOR@WAS; 2026-08-21 printed "WAS -7.23" and "CHI -4.08" on rows whose own win probabilities were 25.2% and 36.5% — the display said favored, the model said heavy underdog. Now mechanical: decision_card.margin_display() + render_gate check #9.
Companion rules from the same review: an observed p_home(v2)-p_home(v1) delta is NOT a causal starter effect until the keyed-seed harness separates it from RNG coupling noise, and crediting a two-slot change to one pitcher is over-attribution; completeness percentages must print numerator, denominator and the NAMED unit, because slots and games give different answers (26/30 slots = 86.7% vs 12/15 games = 80%).
Third instance (2026-08-21, same family): "fully model-resolved games" was printed as 10/15 using daily_card's `capped` flag (gs<2 OR TBD) while the surrounding narrative counted CAP slots (TBD OR registry-miss), which give 11/15. Both correct, different predicates, neither named. Fixed mechanically by unified_card.slot_status()/starter_completeness(), which separate TBD, REGISTRY_MISS, LOW_SAMPLE and RESOLVED and report every count with its predicate. The general rule: whenever two counts of "the same thing" disagree, the defect is an unnamed predicate, not arithmetic.
