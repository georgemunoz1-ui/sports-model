# An audit that only searches where you expect the answer is not an audit — and grep cannot see automation that lives outside the repo.
Rule: when auditing for references to a thing, enumerate the FORMS the thing actually takes, not the forms you expect. For a git branch that means `origin main` (space), `origin/main` (slash), bare `clone` with no -b, `set-head`, and refspec variants. Separately, always enumerate out-of-repo automation (scheduled triggers, external jobs) by tool — no repo-local search can reach it.
Incident: 2026-08-21. I reported "no automation targeting main" after grepping for `origin/main`, `checkout main`, `--branch main` and CI-config patterns. The one real hit was `git push -q origin main` in harness/push.sh:6 — an ordinary push refspec with a space, matched by none of my patterns. Worse, it was a SILENT failure: `main` is a disjoint 2-file stub, so the durability push exited 0 while pushing nothing, and the runbook's WARN-on-failure branch never fired for weeks. A 28-agent audit with an adversarial pass caught it; the fix is `git push -q origin HEAD` (branch-agnostic — hardcoding the new branch name re-creates the same bug class later).
Second half: two enabled cron Routines bare-clone the default branch and were landing on the same stub, an independent cause of recurring BOOTSTRAP_BLOCKED failures that had been attributed solely to a repo-name typo fixed on 2026-08-13. Invisible to grep by construction.
