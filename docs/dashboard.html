Latest patch — ACQUISITION-EXECUTION-2026-08-30 P0

Status: FIXED_AND_ACCEPTANCE_TESTED

The incident. On 2026-08-30 a search for Atlanta Dream availability returned a report 32 days stale. Rejecting it was correct. Terminating on it was not: the run reported AVAILABILITY_UNKNOWN when the correct classification was ACQUISITION_INCOMPLETE. One more query on the same working rail returned the current report immediately. The failure was premature termination and query specificity, not source availability.

Root cause. The repo had an acquisition control plane and no execution plane. route_ladder_v1 already stated that a blocked rail advances the ladder and that acquisition cannot terminate while an authorized route remains untried — but its entry point judges an already-collected set of attempts. It can say “you stopped too soon”; it cannot make anything continue.

Fix. harness/acquisition_orchestrator.py executes the ladder. Every non-acquiring outcome advances — BLOCKED, NOT_FOUND, STALE_REJECTED, CONTAMINATED, TITLES_ONLY, ERROR. disposition() refuses a terminal answer while any authorized rung is untried. assert_no_premature_termination() fails CI when UNKNOWN, BLOCKED or NO_FORECAST is claimed over an unfinished ladder.

Acceptance, live and without an owner upload. Two games, primary rail genuinely blocked. Seven BLOCKED, one NOT_FOUND and one STALE_REJECTED all advanced; current availability, a 12-game MLB slate and a probable starter were acquired at rung 6; forecasts were produced for both games; actionability was gated separately and PASSed for reasons unrelated to forecast availability. ACTION_BLOCKED throughout — wager authority NO, exposure $0.

Residual. MLB MIA@WSH carries no canonical id, because statsapi.mlb.com is blocked on both egress paths and the pitch archive supplies real gamePks only after a game is played. It is forecastable now and not bindable later. No id was invented — the 8/27 pseudo-pk defect is not repeated.
