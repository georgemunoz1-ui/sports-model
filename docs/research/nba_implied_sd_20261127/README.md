The source at `pipelines/cards/semantic_identity.py` separates `digest(features)` and `digest(model)` in the numerical identity. The archived `numeric_inputs.json` files bind the fitted numerical material and individual features independently. One shared model fitted-state hash, eleven different feature snapshot hashes and eleven different event numerical identities are present. `model_fitted_state_sha256` is the clarified alias of `native_numeric_fitted_state_sha256`; the immutable v1 receipt and rows retain their original names. New records should use the clearer name and reject unequal aliases. The combined package model_sha256 binds fit, state and prior and is not a parameter-only partition key.

## Two distinct series

See series_policy.v1.json. Evaluate both independently when eligible. Fixed-fit comparison is conservative and requires exact shared fitted model, transform and prior identity and monitoring policy; ordinary input-state refresh is not a reset. Refit-procedure comparison requires a separately hash-pinned and independently verified training/inference policy manifest and matching run receipts. Same model ID alone does not certify comparability. A daily refit is not a state-only refresh. No verified refit-policy manifest exists for this retained slate. It is not a prospective seed in either series.

Select one first eligible pre-opener snapshot per comparable series/slate, retain refreshes as separate diagnostics, and use only preceding comparable dates within the seven-calendar-day window. Count eligible regression slates separately from actual drift-evaluated slates. The 14 evaluated slate interval is an operational smoke test; the binomial reference is illustrative and cannot certify nominal false-positive rates under dependent rolling baselines.
